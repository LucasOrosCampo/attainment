Attainment: revisión senior y guía práctica de WPF

Un informe accionable sobre la codebase actual y una guía orientada a construir aplicaciones desktop con WPF, XAML, MVVM, inyección de dependencias y EF Core.

.NET 10 / WPFEF Core + SQLiteQuestPDF + PdfPigOpenAI RESTDocumento offline

Resumen ejecutivo

Attainment es un prototipo funcional y pequeño, con una intención arquitectónica correcta —WPF, DI, EF Core y servicios aislados— pero la implementación mezcla MVVM y code-behind, elude el contenedor en varias vistas y contiene defectos que bloquean o rompen flujos importantes.

3

SDK inválido, petición de archivo a IA incompatible y recarga de Settings defectuosa.

1

Sólo cubre el happy path de deserialización del examen.

4

XAML, code-behind/ViewModels, infraestructura y EF Core, sin capa de aplicación clara.

Estado de compilación verificado

dotnet build attainment.sln no llega a ejecutarse: global.json solicita 10.0.0, que no es una versión válida de SDK. Los SDK usan bandas como 10.0.100. La máquina sólo expone el SDK 8.0.416.

Lo que está bien encaminado

  • Las responsabilidades externas ya tienen interfaces (IAi, IPdf), una buena base para pruebas y sustitución.
  • Se usa IDbContextFactory<ApplicationDbContext> en el registro de servicios, que es el patrón adecuado para una app desktop.
  • Los estilos compartidos y converters viven en recursos de aplicación y controles reutilizables.
  • La navegación por páginas y el dominio Subject → Resource → Product son comprensibles.
  • El flujo de examen separa generación, parsing, preview y exportación PDF.

Arquitectura actual

El proyecto usa WPF nativo. No hay una librería de UI externa: XAML es el lenguaje declarativo de WPF, no un framework adicional.

Views / ControlsXAML + eventos en code-behind. Pages alojadas en Frames.
ViewModels parcialesEstado del examen y dos ViewModels casi vacíos.
InfrastructureOpenAI REST, PdfPig, QuestPDF y parser JSON.
PersistenceEF Core 10, SQLite y una migración inicial.

El problema principal no es la elección tecnológica, sino el límite entre capas: la mayoría de páginas instancia su propio ApplicationDbContext, manipula controles por nombre y contiene lógica de aplicación. Por ello DI y MVVM sólo se aplican en una parte del sistema.

Hallazgos priorizados

La prioridad combina impacto funcional, riesgo de datos, seguridad, mantenibilidad y coste de corrección.

P0

global.json bloquea el toolchain

La versión 10.0.0 no representa una banda válida del SDK. rollForward: latestMajor tampoco rescata un valor base inválido. Debe fijarse una versión instalable, por ejemplo 10.0.100, y decidir conscientemente si se permiten previews.

Cambio: fijar SDK válido, añadir instrucciones de bootstrap y validar en CI.

P0

El flujo Base64 de OpenAI mezcla dos APIs incompatibles

El payload usa contenido input_file/input_text, propio de una petición estructurada, pero se envía a /v1/chat/completions, sin model. Ese flujo fallará aunque la clave sea correcta. Además, el contrato devuelve string y oculta el shape de respuesta.

Cambio: escoger una única API, modelar request/response con DTOs y añadir tests HTTP con handler falso.

P1

Reload de Settings intenta recargar una Page como entidad EF

_dbContext.Entry(this).ReloadAsync() trata SettingsPage como una entidad del modelo. EF lanzará una excepción. La recarga debe descartar el contexto o recargar cada entidad registrada.

attainment/Views/SettingsPage.xaml.cs:38

Cambio: mover Settings a un ViewModel/servicio y crear un contexto nuevo por carga o guardado.

P1

Persistencia inconsistente y contextos no liberados

Subjects, Resources, Products y Settings crean ApplicationDbContext con new y lo mantienen durante toda la vida de la Page. Se ignora el factory registrado, crece el change tracker y no hay disposición determinista. Las vistas cargadas por URI XAML tampoco pasan por DI.

Cambio: resolver todas las vistas por DI y usar await using var db = await factory.CreateDbContextAsync() por operación.

P1

EnsureCreated y migraciones se ejecutan juntos

EnsureCreated evita el historial normal de migraciones y no debe mezclarse con Migrate en una base destinada a evolucionar. También falta garantizar el directorio cuando las opciones ya vienen configuradas por DI, porque OnConfiguring no entra en esa rama.

Clave API en texto plano y caché que no se invalida

La clave se guarda en SQLite sin protección y OpenAi la conserva en _apiKey. Tras editar Settings, el singleton puede seguir usando el valor anterior. Además, el contexto creado para leerla no se dispone.

Roadmap recomendado

Qué librería de escritorio usa el proyecto

Attainment usa WPF nativo

WPF (Windows Presentation Foundation) es el framework desktop de .NET para Windows. XAML describe el árbol visual; C# aporta comportamiento, ViewModels y servicios. No hay Material Design, WPF UI, MahApps u otro toolkit visual instalado.

Generic Host

DI, configuración y logging de Microsoft.Extensions.*.

PdfPig

Lectura y extracción de texto de PDF.

QuestPDF

Generación de documentos PDF desde C#.

xUnit

Framework de pruebas automatizadas.

Modelo mental de XAML

Piensa en XAML como una forma declarativa de crear objetos .NET y colocarlos en un árbol. Cada etiqueta suele ser una clase; cada atributo, una propiedad.

<Grid Margin="20">
  <Grid.RowDefinitions>
    <RowDefinition Height="Auto"/>
    <RowDefinition Height="*"/>
  </Grid.RowDefinitions>

  <TextBlock Text="Mis recursos" FontSize="24"/>
  <ListBox Grid.Row="1" ItemsSource="{Binding Resources}"/>
</Grid>
  • Auto: la fila mide lo que necesita su contenido.
  • *: consume el espacio restante; 2* consume el doble que *.
  • Grid: layout principal y predecible. StackPanel: secuencia simple. DockPanel: bordes. WrapPanel: tarjetas que saltan de línea.
  • x:Name crea una referencia accesible desde code-behind, pero en MVVM se usa con moderación.
  • StaticResource busca estilos, brushes o converters declarados en Resources.

Binding y MVVM

El binding conecta propiedades del control con propiedades del DataContext. En una Page MVVM, el DataContext suele ser su ViewModel.

public sealed class SubjectsPageViewModel : INotifyPropertyChanged
{
    public ObservableCollection<SubjectListItem> Subjects { get; } = [];

    private string _searchText = string.Empty;
    public string SearchText
    {
        get => _searchText;
        set
        {
            if (_searchText == value) return;
            _searchText = value;
            PropertyChanged?.Invoke(this,
                new PropertyChangedEventArgs(nameof(SearchText)));
        }
    }

    public ICommand RefreshCommand { get; }
    public event PropertyChangedEventHandler? PropertyChanged;
}
<TextBox Text="{Binding SearchText,
                Mode=TwoWay,
                UpdateSourceTrigger=PropertyChanged}"/>

<Button Content="Actualizar" Command="{Binding RefreshCommand}"/>

<ListBox ItemsSource="{Binding Subjects}">
  <ListBox.ItemTemplate>
    <DataTemplate>
      <TextBlock Text="{Binding Name}"/>
    </DataTemplate>
  </ListBox.ItemTemplate>
</ListBox>
SintaxisUso
{Binding Name}Lee DataContext.Name.
Mode=TwoWayUI ↔ ViewModel, típico en formularios.
OneWayViewModel → UI, típico en resultados.
UpdateSourceTrigger=PropertyChangedActualiza en cada pulsación, útil para búsquedas.
RelativeSourceBusca otro elemento/ancestro cuando el DataContext actual no basta.
ConverterTransforma valor visual; no debe contener lógica de negocio.
Regla práctica

Si un click ejecuta un caso de uso, usa un ICommand. Si sólo mueve el foco, abre una animación o interactúa con un detalle visual, el code-behind es aceptable.

DI, ciclo de vida y navegación

WPF no obliga a usar DI, pero Attainment ya usa Generic Host. La mejora consiste en hacer que todas las Pages, ViewModels y servicios entren por el mismo composition root.

services.AddDbContextFactory<ApplicationDbContext>(options =>
    options.UseSqlite(connectionString));

services.AddSingleton<INavigationService, NavigationService>();
services.AddSingleton<IAiClient, OpenAiClient>();
services.AddSingleton<IPdfService, PdfService>();

services.AddTransient<SubjectsPageViewModel>();
services.AddTransient<SubjectsPage>();
services.AddTransient<ResourcePageViewModel>();
services.AddTransient<ResourcePage>();

Evita service locator

App.Services.GetRequiredService<T>() desde una Page oculta dependencias. Prefiere inyectar INavigationService en el ViewModel y pedir navegación con parámetros tipados.

public interface INavigationService
{
    void NavigateTo<TViewModel>(object? parameter = null);
    bool CanGoBack { get; }
    void GoBack();
}

public sealed class SubjectsPageViewModel(INavigationService navigation)
{
    public ICommand OpenSubjectCommand => new RelayCommand<SubjectListItem>(
        subject => navigation.NavigateTo<ResourcePageViewModel>(subject.Id));
}

EF Core y SQLite en desktop

En WPF, una Page puede vivir mucho tiempo. Un DbContext no debería vivir lo mismo: usa el factory y crea un contexto corto por operación.

public sealed class SubjectService(
    IDbContextFactory<ApplicationDbContext> dbFactory)
{
    public async Task<IReadOnlyList<SubjectListItem>> GetAllAsync(
        CancellationToken cancellationToken)
    {
        await using var db = await dbFactory.CreateDbContextAsync(cancellationToken);

        return await db.Subjects
            .AsNoTracking()
            .OrderBy(subject => subject.Name)
            .Select(subject => new SubjectListItem(
                subject.Id,
                subject.Name,
                subject.Description,
                subject.IsFavorite,
                subject.Resources.Count))
            .ToListAsync(cancellationToken);
    }
}
  • AsNoTracking para lecturas que no editarás.
  • Proyecta DTOs/list items; no enlaces entidades EF vivas directamente a toda la UI.
  • Una operación de escritura abre contexto, carga/valida, modifica, guarda y lo cierra.
  • Usa migraciones para producción. No combines EnsureCreated con Migrate.
  • Las reglas esenciales deben existir también como constraints/índices de base de datos.

Inicialización recomendada

Directory.CreateDirectory(ApplicationDbContext.DatabaseDirectory);

await using var scope = host.Services.CreateAsyncScope();
var factory = scope.ServiceProvider
    .GetRequiredService<IDbContextFactory<ApplicationDbContext>>();
await using var db = await factory.CreateDbContextAsync();
await db.Database.MigrateAsync();

Asincronía que no congela la UI

Toda interacción WPF empieza en el thread UI. I/O de red, disco o base de datos debe ser async de extremo a extremo. Usa Task.Run sólo para trabajo realmente CPU-bound sin API asíncrona.

public interface IAiClient
{
    Task<Exam> GenerateExamAsync(
        ExamGenerationRequest request,
        CancellationToken cancellationToken);
}

public async Task GenerateExamAsync(CancellationToken cancellationToken)
{
    if (IsLoading) return;

    try
    {
        IsLoading = true;
        ErrorMessage = null;
        ParsedExam = await aiClient.GenerateExamAsync(
            BuildRequest(), cancellationToken);
    }
    catch (OperationCanceledException)
    {
        StatusMessage = "Operación cancelada";
    }
    catch (AiClientException exception)
    {
        logger.LogWarning(exception, "Exam generation failed");
        ErrorMessage = "No se pudo generar el examen.";
    }
    finally
    {
        IsLoading = false;
    }
}
  • Deshabilita el comando mientras IsLoading.
  • Expón cancelación para operaciones largas.
  • Configura timeout del cliente HTTP y límites de tamaño de archivo.
  • No muestres mensajes internos de excepción al usuario; regístralos con ILogger.
  • El retorno de la API debe ser tipado; evita transportar JSON crudo por toda la UI.

Añadir una funcionalidad de principio a fin

Ejemplo: añadir “Notas” a un recurso siguiendo una vertical slice mantenible.

Modela el caso de uso

Define Note con invariantes (ResourceId válido, texto requerido, fecha UTC). No empieces por el botón.

Actualiza persistencia

Añade DbSet<Note>, configuración Fluent API, índice y migración. Prueba con SQLite real en un directorio temporal.

Crea un servicio de aplicación

INoteService.GetForResourceAsync, CreateAsync y DeleteAsync. Usa IDbContextFactory.

Crea el ViewModel

Estado observable, validación, LoadCommand, SaveCommand, DeleteCommand y estados de carga/error.

Diseña la vista XAML

Bindings y DataTemplates; sin acceso directo a EF. Añade labels, orden de tabulación y AutomationProperties.Name.

Registra en DI y navegación

Registra servicio, ViewModel y Page. Navega con ResourceId, no pasando una entidad EF trackeada.

Cubre riesgos con tests

Validación del dominio, servicio con SQLite, comandos del ViewModel y un smoke test de resolución DI.

Depuración y pruebas

Cuando un binding no funciona

  1. Verifica el DataContext real de ese elemento.
  2. Mira la ventana Output de Visual Studio/Rider: WPF escribe errores de binding.
  3. Comprueba nombre y visibilidad pública de la propiedad.
  4. Para cambios posteriores, implementa INotifyPropertyChanged.
  5. Para listas mutables, usa ObservableCollection<T>.
  6. Revisa que el converter esté registrado y que no lance excepciones.

Comandos de trabajo

Primero corrige o instala el SDK

El repositorio actual no compila con global.json: 10.0.0. Usa una banda real compatible con el proyecto, como 10.0.100, y asegúrate de tener el workload/runtime Windows Desktop correspondiente.

# Ver SDK efectivo y diagnóstico
dotnet --info

# Restaurar, compilar y probar
dotnet restore attainment.sln
dotnet build attainment.sln --configuration Debug
dotnet test attainment.sln --configuration Debug --no-build

# Ejecutar la app
dotnet run --project attainment/attainment.csproj

# Crear y aplicar migración
dotnet ef migrations add NombreMigracion --project attainment
dotnet ef database update --project attainment

# Publicar Windows x64 autocontenido
dotnet publish attainment/attainment.csproj \
  --configuration Release \
  --runtime win-x64 \
  --self-contained true

En PowerShell, usa el acento grave (`) en lugar de \ para continuar una orden en varias líneas, o ejecuta la orden en una sola línea.

Checklist antes de integrar cambios

Arquitectura

  • La View no accede a EF ni HTTP.
  • Las dependencias llegan por constructor.
  • El contexto vive una operación.
  • La navegación usa IDs/DTOs, no entidades trackeadas.
  • Las invariantes viven fuera de XAML.

UX y robustez

  • Hay loading, error, vacío y éxito.
  • Se puede cancelar lo largo.
  • Teclado y lector de pantalla tienen soporte.
  • Los errores técnicos se registran, no se exponen.
  • Los borrados destructivos se confirman.

Datos y seguridad

  • Migración creada y probada.
  • Constraints respaldan reglas críticas.
  • Secretos no están en texto plano.
  • No se registran claves ni contenido sensible.
  • Rutas y tamaños de archivo se validan.

Entrega

  • Build limpio en Debug y Release.
  • Tests específicos y suite completa pasan.
  • La app arranca con base vacía.
  • La documentación refleja cambios.
  • Dependencias y licencias están revisadas.
